# 建仓与部署手册（手动操作版）

> 适用：Windows + Git Bash / PowerShell，作业截止 2026-11-17 23:59。
> 本文只写"你要亲手敲的命令"和"网页上要点哪里"，代码本身不需要改。

---

## 0. 总览

| 步骤 | 内容 | 预计耗时 | 能否省略 |
|---|---|---|---|
| 1 | GitHub 网页建仓库 | 5 min | 不能 |
| 2 | 本地初始化 + 6 次提交 + 推送 | 15 min | 不能 |
| 3 | 换目录 clone 验证仓库可构建 | 10 min | 强烈建议不要省 |
| 4 | 买/开云服务器，放行端口 | 10 min | 想拿 +15 分就不能省 |
| 5 | 服务器部署（命令行或宝塔） | 30 min | 同上 |
| 6 | 回填博客并发布 | 30 min | 不能 |

**先做 1–3，再决定要不要做 4–5。** 仓库和博客是 100 分基本盘，云部署只是加分项，顺序不能反。

## 1. GitHub 网页建仓库

### 1.1 新建

登录 GitHub → 右上角 `+` → **New repository**，按下表填写：

| 字段 | 填什么 | 注意 |
|---|---|---|
| Repository name | `address-book` | 用英文，不要空格和中文 |
| Description | `通讯录：收藏 / 多联系方式 / Excel 导入导出` | 可选 |
| Public / Private | **Public** | 私有仓库老师打不开，需要逐个邀请，助教不会来问你要邀请 |
| Add a README file | **不勾** | 本地已有代码，勾了会产生一条无关历史，push 时必报冲突 |
| Add .gitignore | **不勾** | 本地已有 |
| Choose a license | **不勾**（None） | 需要时后面补 |

点 **Create repository**，进入空仓库页面，复制 HTTPS 地址：

```
https://github.com/<你的用户名>/address-book.git
```

> 建完是空仓库页面（显示 "Quick setup"）才是对的。如果页面上已经有 README，说明你勾了初始化选项，看本文 2.5 的 `rejected` 处理。

### 1.2 顺便准备提交身份

在 GitHub 网页右上角头像 → **Settings → Emails**，找到 `xxxxx@users.noreply.github.com` 形式的邮箱。

**建议用它作为 git 邮箱**：公开仓库的 commit 记录会暴露邮箱，用 noreply 邮箱可以避免真实邮箱被爬。

## 2. 本地初始化并分 6 次提交

> **这一段在哪里执行？在你自己电脑上，不是服务器上。**
>
> | 项 | 说明 |
> |---|---|
> | 哪台机器 | 你的 Windows 电脑（代码就在这台机器上） |
> | 哪个目录 | 项目根目录 `...\address-book`，即能看到 `package.json` 的那一层；**不是** `server` 或 `public` 子目录 |
> | 什么终端 | 开始菜单搜 **Git Bash**（推荐，命令与本手册完全一致），或 PowerShell。CMD 也可用，但 `cd "E:/..."` 要写成 `cd /d "E:\..."` |
> | 什么时候 | 第 1 节在网页上建完空仓库之后，第 5 节上服务器之前 |
> | 跑几次 | `git init` 每个项目只跑一次；`git add/commit` 每次改动后跑；这一段总共跑一次即可 |
>
> 与第 5 节的区别：**本地只 `git init` + `push`，服务器上只 `git clone`，绝不要在服务器上 `git init`。**
> 本节全部命令只改动本地 `.git` 目录和 GitHub 上的仓库，不会碰你的源码内容。

### 2.1 配置身份（全局只需一次）

```bash
git config --global user.name  "你的名字"
git config --global user.email "你的GitHub邮箱或noreply邮箱"
```

顺手加两条 Windows 上很有用的配置：

```bash
git config --global core.longpaths true    # 避免路径过长报错
git config --global core.quotepath false   # 中文文件名不显示成 \344\275\240
```

### 2.2 进入项目目录

```bash
cd "E:/WorkBuddy Documents/2026-11-16-20-21-22/address-book"
ls        # 应能看到 package.json、server、public、docs
git init
```

> **若 `git log --oneline` 已经能看到 6 条提交，说明仓库已初始化过，此时不要再执行 `git init` 与 `git add/commit`，直接跳到 2.4 的推送即可。**

`git init` 后**不要**急着 `git add .`。作业要看"分模块提交"，一次全提交虽然也能过，但 commit 历史只有 1 条，博客里没法展示分工过程。

### 2.3 逐条执行 6 次提交

每执行完一条 `git add`，建议先 `git status --short` 看一眼清单对不对，再 commit。

```bash
# ① 工程骨架与依赖（锁文件必须一起提交，保证别人能装出同样的依赖树）
git add package.json package-lock.json .gitignore .gitattributes
git commit -m "chore: 初始化项目结构与依赖"

# ② 数据层：建表 + 全部 SQL
git add server/db.js server/repository.js
git commit -m "feat: 联系人数据模型与仓储层（收藏、多联系方式）"

# ③ Excel 读写
git add server/excel.js
git commit -m "feat: Excel 导入导出（表头别名、重复合并、样式）"

# ④ 接口与服务入口
git add server/index.js server/routes
git commit -m "feat: REST 接口、收藏切换与静态资源服务"

# ⑤ 前端
git add public
git commit -m "feat: 前端页面、收藏筛选与动态联系方式编辑"

# ⑥ 文档与演示数据
git add docs README.md scripts
git commit -m "docs: 补充部署文档、代码规范与作业博客"
```

```bash
git log --oneline    # 应看到 6 条提交
```

### 2.4 关联远程并推送

```bash
git branch -M main
git remote add origin https://github.com/<你的用户名>/address-book.git
git push -u origin main
```

**认证方式**（二选一）：

- 方式 A：会弹出一个 GitHub 登录窗口，点 **Sign in with your browser**，浏览器授权后自动完成；
- 方式 B：弹窗不出现或一直失败，用 **Personal Access Token**：
  GitHub → Settings → Developer settings → Personal access tokens → **Tokens (classic)** → Generate new token → 勾选 `repo` → 生成后复制，**push 时把它当成密码粘贴**。

> Token 只显示一次，先复制到记事本。用 PAT 时用户名填你的 GitHub 用户名，密码填 token。

### 2.5 常见报错对照

| 报错 | 原因 | 处理 |
|---|---|---|
| `remote: Support for password authentication was removed` | 用了账号密码而不是 token | 改用 2.4 的方式 B |
| `! [rejected] main -> main (fetch first)` | 建仓时勾了 README/.gitignore，远程已有提交 | `git pull --rebase origin main` 后重新 `git push -u origin main` |
| `fatal: remote origin already exists` | 之前配过远程地址 | `git remote set-url origin <正确地址>` |
| `warning: LF will be replaced by CRLF` | Windows 换行符 | 无害，可忽略（项目已带 `.gitattributes`） |
| `fatal: unable to access ... Could not resolve host` | 网络/DNS | 换网络，或先 `git config --global http.proxy` 配代理 |
| `error: src refspec main does not match any` | 还没产生任何提交 | 先完成 2.3 的 6 次提交 |
| 中文文件名显示成 `\346\226\207...` | 编码显示设置 | `git config --global core.quotepath false` |

## 3. 推送后验证（别跳过）

作业明确要求"代码应允许项目被构建"。**验证方式就是换一个目录重新 clone 一遍并跑起来**——这一步能提前发现"某个文件忘了提交"这类致命问题。

```bash
cd /d/temp          # 或任意空目录
git clone https://github.com/<你的用户名>/address-book.git verify
cd verify
npm install
npm start
```

浏览器打开 `http://localhost:3000`，新建一条联系人，刷新页面确认数据仍在，即说明仓库完整可用。

验证完可以删掉 `verify` 目录。

**顺手截两张图**（博客要用）：

1. GitHub 仓库页面 → `Insights` → `Commits`，截图提交历史；
2. 仓库首页右侧 `Contributors`，或本地执行 `git shortlog -sn`，截图提交次数统计。

## 5. 部署执行（最小可行路径）

### 5.1 七步上线

```bash
# ① 登录服务器（在你自己电脑的终端里执行）
ssh root@<你的公网IP>

# ② 装 Node 20 与编译工具（better-sqlite3 是原生模块，可能需要编译）
apt update && apt install -y curl git build-essential python3
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs
node -v    # 应输出 v20.x

# ③ 拉代码（用自己的仓库地址）
cd /opt
git clone https://github.com/<你的用户名>/address-book.git address-book
cd address-book

# ④ 装生产依赖
npm install --omit=dev

# ⑤ 用 PM2 常驻运行，直接监听 80
npm install -g pm2
PORT=80 pm2 start server/index.js --name address-book

# ⑥ 立刻验证
curl http://127.0.0.1/api/health         # 返回 {"success":true,...}
# 然后在浏览器打开 http://<公网IP> 看页面

# ⑦ 开机自启
pm2 save
pm2 startup        # 按它输出的那行命令原样再执行一次
```

到此已经可以访问公网地址。**先确认这一步成功，再去折腾 Nginx 和域名**，否则出问题分不清是哪一层。

### 5.2 可选增强

| 需求 | 做法 |
|---|---|
| 绑定域名 / HTTPS | 先按 `docs/deploy.md` 第 6 节配 Nginx 反代，再用 `certbot` 签证书 |
| 应用只监听本地 | Nginx 里 `proxy_pass http://127.0.0.1:3000`，启动改 `PORT=3000 HOST=127.0.0.1` |
| 上传 Excel 报 413 | Nginx 加 `client_max_body_size 12m;` 后 `systemctl reload nginx` |
| 备份数据 | `docs/deploy.md` 第 8 节的定时任务 |
| 不熟悉命令行 | `docs/deploy.md` 第 9 节的宝塔面板 7 步 |

### 5.3 部署常见故障

| 现象 | 排查顺序 |
|---|---|
| 浏览器打不开、curl 本地正常 | ① 安全组是否放行 80；② `ss -lntp \| grep :80` 看进程是否在听 |
| `pm2 status` 显示 errored | `pm2 logs address-book` 看真实报错，多为端口占用或缺依赖 |
| 页面能开但数据不保存 | `ls -l /opt/address-book/data`，检查目录存在且可写 |
| `better-sqlite3` 安装失败 | 确认已装 `build-essential python3`，再 `npm rebuild better-sqlite3` |
| 重启服务器后 502 | 没做 `pm2 startup` + `pm2 save` |
| 中文文件名下载乱码 | 项目已用 RFC 5987 编码，正常浏览器无此问题；若仍乱码检查 Nginx 是否改写响应头 |
