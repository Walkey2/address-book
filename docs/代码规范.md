# 代码规范（Code Style）

本项目采用「轻量约定 + 目录即边界」的方式，规则少但每条都强制。评审或接手时按本文逐条对照即可。

## 1. 目录与分层

| 目录 / 文件 | 职责 | 禁止事项 |
|---|---|---|
| `server/index.js` | 应用装配：中间件、静态资源、错误处理、进程退出 | 不写业务逻辑、不写 SQL |
| `server/routes/*.js` | HTTP 语义：参数校验、状态码、响应结构 | 不写 SQL，不直接操作文件 |
| `server/repository.js` | 数据访问：全部 SQL 与事务 | 不碰 `req` / `res` |
| `server/db.js` | 连接、建表、索引、枚举常量 | 不写查询语句 |
| `server/excel.js` | 文件格式转换 | 不访问数据库 |
| `public/` | 前端页面，无构建步骤 | 不引入框架与打包工具 |

**判断标准**：如果一个函数的参数里同时出现 `req` 和 `SELECT`，说明分层被破坏了。

## 2. 命名

- 文件、目录：小写短横线（`contact-methods.js`）或小写单词（`repository.js`）；
- 变量与函数：小驼峰 `listContacts`、`normalizeMethods`；
- 常量与枚举：全大写下划线 `MAX_SLOTS`、`METHOD_TYPE_VALUES`；
- 数据库：表名复数小写 `contacts`，字段小写下划线 `contact_id`、`created_at`；
- 布尔量加前缀：`favorite`、`favoriteOnly`、`isActive`，前端 DOM 状态类用 `is-` 前缀（`is-active`）。

## 3. JavaScript

- 服务端与前端脚本首行统一 `'use strict';`；
- 只用 `const` / `let`，禁用 `var`；
- 函数保持单一职责，超过 50 行必须拆分；
- 异步统一 `async / await`，不用回调嵌套；
- 早返回（early return）替代深层 `if` 嵌套；
- 字符串拼接多行 HTML 用模板字符串，插入用户数据必须经 `esc()` 转义。

## 4. 数据库

- 所有 SQL 使用**参数化查询**（`?` 或 `@name`），禁止字符串拼接用户输入；
- 多表写入必须包在 `db.transaction()` 中，保证原子性；
- 删除联系人依赖外键 `ON DELETE CASCADE`，不在业务代码里手动删两张表；
- 新增字段一律给默认值，避免 `NULL` 参与比较。

## 5. API 约定

- 路径用复数名词 + HTTP 动词表达语义：`DELETE /api/contacts/12`；
- 响应统一为 `{ success, data, message }`；
- 状态码：200 成功、201 新建、400 参数错误、404 不存在、500 服务端异常；
- 错误信息面向使用者，不把堆栈或 SQL 报错原文抛给前端。

## 6. 前端

- 不使用内联事件属性（`onclick="..."`），统一事件委托绑定在容器上；
- 所有插入 DOM 的文本经 `esc()` 转义，防 XSS；
- 状态集中在 `state` 对象，渲染函数只读状态、不反向修改；
- 交互反馈必须可见：成功/失败均有 Toast，危险操作有二次确认。

## 7. Git 提交

提交信息格式：`类型: 摘要`，类型取以下之一：

| 类型 | 用途 |
|---|---|
| `feat` | 新功能 |
| `fix` | 修复缺陷 |
| `docs` | 文档 |
| `style` | 样式与格式（不影响逻辑） |
| `refactor` | 重构 |
| `test` | 测试 |
| `chore` | 构建、依赖、配置 |

示例：

```
feat: 支持联系人收藏与收藏筛选
feat: 实现 Excel 导入导出
fix: 修复隐藏元素覆盖页面导致点击失效
docs: 补充云服务器部署文档
```

一次提交只做一件事，摘要不超过 50 字符，需要时在正文补充动机与影响范围。

## 8. 注释

- 注释解释**为什么**，不复述代码在做什么；
- 每个模块顶部写一段职责说明；
- 涉及业务规则的地方（如导入去重规则）必须写明判定条件。
